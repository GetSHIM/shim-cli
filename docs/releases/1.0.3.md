# shim-cli 1.0.3

## Secrets with a name

On 29 September a live Claude Code session read a synthetic `.env` with shim
installed, and the model told the user, in its own words, that
`AWS_SECRET_ACCESS_KEY`, `SLACK_BOT_TOKEN` and `LEDGER_API_TOKEN` had not been
masked. The secret rule only started when the key *was* the secret word, so
`password=` was caught and `DB_PASSWORD=` was not, and six vendor formats were
missing.

A secret word now counts anywhere in a key name (`DB_PASSWORD`,
`KIS_APP_SECRET_LIVE`, `client.secret`, `x-api-key`, `clientSecret`), and Slack,
Google, fine-grained GitHub, GitLab, npm and Hugging Face tokens, Azure storage
`AccountKey` values and HTTP `Authorization` headers are found by their shape.
Of the eighteen lines of that probe, 1.0.2 masked five and 1.0.3 masks all
eighteen. `MAX_TOKENS=4096`, `TOKEN_TTL=3600`, `PASSWORD_MIN_LENGTH=12` and
`SORT_KEY=name` stay quiet, and so do references such as `${DB_PASS}` and type
annotations such as `apiKey: string`.
Code that only names a secret stays quiet as well: `"token_type": "Bearer"`,
`api_key_header = "X-Api-Key"`, `token_ids = tokenizer.encode(text)` and
`auth_token = self.auth_token`.
