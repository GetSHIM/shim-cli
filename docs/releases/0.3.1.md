# shim-cli 0.3.1

A documentation release, plus the three defects that writing the documentation
found. Nothing in it changes what shim detects or what it does to your text.

Upgrading is `uv tool upgrade shim`, or `/plugin update shim-cli@shim-cli` in
Claude Code. There is nothing to migrate.

## A command reference

`docs/commands.md` documents every command, every flag, the exit codes, every
key in `config.toml`, the environment variables shim reads, and where it keeps
things on disk.

Before this, three commands — `shim update`, `shim demo` and `shim status` —
appeared in no documentation at all, and no page listed the exit codes or the
settings keys. Every example in the reference was run against the built CLI and
pasted back rather than written from memory, which is how the rest of this
release happened.

## `shim watch --help` now documents `shim watch`

It printed `Usage: shim watch [OPTIONS]` and listed `--json` and `--help`. The
client goes after `--`:

```console
shim watch -- claude
shim watch -- claude -p "explain this repo"
```

That is the whole point of the command, and its own help never said so. It now
shows both forms and states that the proxy is Claude Code only.

## A refused settings file says which check refused it

shim inspects its settings file before reading it and declines a symlink, a
hard link, a file it does not own, one another user can write, one over the
inspection limit, or one that changes while being read. Every one of those was
reported as:

```
Entity settings are unsafe or invalid; reset malformed contents or review the path.
```

which named neither the file, the check, nor a way out — and 0.3.0's
improvement to that message went the other way, telling every case to fix file
permissions. A symlinked config in a private directory was answered with advice
about modes it already had.

Each refusal now names its own cause:

```
FAIL Settings at ~/.config/shim/config.toml were refused: target must not be
a symlink.
```

For the ownership and writability cases the message also says why, because
there the reason is the argument: anything that can rewrite your settings can
turn detection off. A parse failure still gets the parser's message with its
line number and `shim config --reset`.

## A failed removal no longer reports success

`shim revert copilot` printed `removed the old hook file at ...` even when the
unlink failed. The file stayed, `shim doctor` kept naming it, and you had been
told it was gone.

## Verified

`python scripts/check.py` green on 3.10 and 3.13: 1,891 tests, lint, format,
types, and a package build. The committed zero-install archive is byte
identical to a fresh build and answers identically on Python 3.9 and 3.13,
including for non-ASCII text. No open code-scanning or dependabot alerts.

Client versions and what was verified live are unchanged from 0.3.0; see
[compatibility.md](../compatibility.md).
