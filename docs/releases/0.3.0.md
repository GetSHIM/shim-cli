# shim-cli 0.3.0

This release finishes the rename. The product is `shim-cli`, the command is
`shim`, the PyPI distribution stays `shim`, and the importable package moves
from `shim_guard` to `shim_cli`. Everything the tool has ever written on your
machine — settings, ledger, session spool, the Copilot hook file and the hook
line inside your client's configuration — moves to the new name as a side
effect of commands you already run. There is no behaviour change in detection,
masking or reporting.

## Upgrading from 0.2.0

Nothing breaks and nothing is required of you. The hook command your client
already runs, `<python> -I -B -m shim_guard.hook <client>`, keeps working byte
for byte: the wheel ships a two-file `shim_guard` package that re-exports the
new one. It emits no deprecation warning, because the hook is a cold-start
subprocess whose stderr your client shows you on every event.

When convenient, run `shim install <client>` once. That rewrites the hook line
to the new module name in place — it does not append a second one — and on
Copilot replaces `hooks/shim-guard.json` with `hooks/shim.json`. `shim doctor
<client>` names every old-shape item it finds and the command that fixes it,
and changes nothing itself.

Claude Code plugin users need no action: `shim-guard@shim-guard` still resolves
through a marketplace alias entry and updates in place.

**Codex plugin users are the exception.** On Codex the marketplace name in the
manifest is the identity, so renaming it orphans an install made under the old
name: `config.toml` still says the plugin is enabled while `codex plugin list`
reports nothing installed. A plugin-level alias cannot fix that. Run:

```console
codex plugin remove shim-guard
codex plugin marketplace remove shim-guard
codex plugin marketplace add https://github.com/GetSHIM/shim-cli
codex plugin add shim-cli@shim-cli
```

This affects the plugin only, not a Codex user who installed the PyPI package.

## Paths that moved

| What | 0.2.0 | 0.3.0 |
| --- | --- | --- |
| Settings | `<config home>/shim-guard/config.toml` | `<config home>/shim/config.toml` |
| Settings variable | `SHIM_GUARD_CONFIG` | `SHIM_CONFIG` |
| Opt-in ledger | `<state home>/shim-guard/` | `<state home>/shim/` |
| Session spool | `$TMPDIR/shim-guard-session-<uid>` | `$TMPDIR/shim-session-<uid>` |
| Copilot hook file | `~/.copilot/hooks/shim-guard.json` | `~/.copilot/hooks/shim.json` |
| Redacted prompt files | `$TMPDIR/shim-guard-redacted-*` | `$TMPDIR/shim-redacted-*` |
| Plugin directory | `plugins/shim-guard/` | `plugins/shim-cli/` |
| Plugin launcher | `hooks/run-shim-guard` | `hooks/run-shim` |

The hook never performs a move. It reads the new location and falls back to the
old one, so it stays read-mostly and fast. `shim config`, `shim install`, `shim
report` and `shim ledger purge` do the moving, report each move once, and cannot
repeat it because the old file is gone.

A session that straddles the upgrade loses the counts from before it in its
summary, because the spool prefix changed and has no fallback. `SessionEnd`
deletes the spool anyway.

## Deprecated names

All four are removed in **0.5.0**, the second minor release after this one:

| Name | Replacement |
| --- | --- |
| the `shim_guard` package, including `python -m shim_guard.hook` | `shim_cli`, `python -m shim_cli.hook` |
| the `shim-guard-hook` console script | `shim-hook` |
| the `SHIM_GUARD_CONFIG` variable | `SHIM_CONFIG`, which outranks it |
| the `shim-guard` marketplace entry | the `shim-cli` entry |

The user-visible block reason changed with the name: a blocked prompt now reads
`shim blocked this prompt: EMAIL (1).` rather than `SHIM Guard blocked ...`.

## Python support

The package floor is CPython 3.10 (`b360d94`, 2 September). `rich` and `typer`
do not support 3.9, and the security alerts closed in that commit were in those
two.

The plugin's bundled hook archive is a separate question and now runs on **3.9**.
Its interpreter gate was 3.10 by policy, not by need: the archive is standard
library plus the vendored `tomli` and `phonenumbers`. A stock macOS with only
the Xcode command-line tools has `python3` 3.9.6, so the zero-install plugin
was refusing to inspect anything on exactly the machine it was built for. The
archive now answers byte-identically on 3.9 and 3.13 for a prompt block, a
`PostToolUse` masking event and a `Stop` summary, and CI diffs the two on every
pull request. On 3.8 it prints one line and exits 0 without blocking.

The Codex plugin also reaches the archive for the first time. Its launcher read
`CLAUDE_PLUGIN_ROOT`, which Codex does not set, so the zero-install path was
dead there; the root is now passed as an argument.

## Behaviour from PR #12 that you may see

These landed on `main` before this release and are visible to users:

- `shim watch` refuses to start when the client's base-URL variable is already
  set, rather than silently competing with it.
- A request that uses chunked framing is rejected with 400.
- Usage is measured after the response has been relayed, with two concurrent
  measurement slots and no queue. In a session with parallel sub-agents some
  requests are forwarded without inspection; the report says how many, and
  reports usage as `known`, `partial` or `unavailable`.

## Release evidence

The local gate is green — lock, lint, format, types, 1,856 tests, wheel and
source distribution — and `release.yml` re-runs it on the tagged tree before
publishing anything, rebuilding from a clean snapshot and requiring the fresh
build to match the tested artifacts.

Two clients were exercised against a running install for this release: Claude
Code 2.1.263, for the hook and for `shim watch` in both directions, and Codex
CLI 0.151.0, for the prompt hook under `observe` and `enforce`. GitHub Copilot
CLI was **not** re-verified for 0.3.0; its install and diagnosis paths are
covered by the suite and the tested version stays 1.0.80.

`shim watch -- codex` is refused in this release. The proxy would have been
bypassed: Codex takes its endpoint from its own configuration and ignores the
environment variable the command was setting, so the session ran past the proxy
and reported an empty measurement. The transport itself was probed and works.

The full scope, including what was not verified, is in
[`docs/compatibility.md`](../compatibility.md).
