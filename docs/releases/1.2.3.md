# shim-cli 1.2.3

1.2.3 closes most of the gaps the 1.2.2 notes listed under "Known gaps, fixed
in 1.2.3". A placeholder the model writes back into a file is now refused, a
value keeps one placeholder number across a whole event, keys and numbers in a
tool's JSON are inspected, and the detector reads more secret shapes while
masking exactly the value. Session records no longer drop or keep what they
should not, and the hook answers before the client stops waiting, even on a
starved machine. Three of the listed gaps are not fixed: detector throughput
on number-dense text, the pattern coverage batch, and refusals of MCP calls on
detector noise. They are under "Known gaps" at the end, with what they still
cost.

**The hook protocol changed again in places:** a write can now be refused in
every mode, a tool result can be withheld after it was inspected, and a few
messages and exit codes changed. Read "What to check after upgrading" before
you upgrade a setup that scripts around shim.

Upgrading is `uv tool upgrade shim` or `pipx upgrade shim`, or
`/plugin update shim-cli@shim-cli` in Claude Code; for VS Code, check out the
`v1.2.3` tag in the folder you cloned. `shim install` writes the same entries
as in 1.2.2.

## A placeholder is never written back

In 1.2.2, after a masked `Read` the model held `<SECRET_1>` where the file held
the key, and a `Write` or `Edit` of what it saw put the placeholder over the
real value on disk, with no warning, even under `local-write = "enforce"`.

- **The write is refused, in every mode.** A `Write`, `Edit`, `MultiEdit` or
  `NotebookEdit`, a VS Code edit tool (for `apply_patch`, its added lines), or
  any MCP or unknown tool call whose new text holds a placeholder shim issued
  in this session is denied: `shim: this Write call would write <SECRET_1>, a
  placeholder shim gave you in place of a real value, instead of that value.
  Change the real value another way, or ask the user.` The text an edit
  replaces is not new text, so an edit that removes a placeholder goes through.
- **Only placeholders shim issued count.** `<EMAIL_1>` in a doc or a test
  fixture, where shim never issued it in this session, is written as it is,
  and so is the same write in another session. To tell the two apart, shim
  keeps the names it issued beside the session record: a type and a range of
  numbers per line, such as `EMAIL 1 3`, never a value. A masked tool result,
  the redacted copy of a prompt blocked under `enforce` and the prompt Copilot
  is given in place of yours all issue names. The store has its own cap, so a
  full session log cannot drop it, and `SessionEnd` deletes it with the log.
- **It fails closed.** If the names cannot be read, a write holding
  placeholder-shaped text is refused; if they cannot be kept, a masked result
  is not handed on.
- Shell commands are not read for placeholders, and Codex and GitHub Copilot
  CLI send shim no tool event, so there is no write to refuse there. The
  session summary does not list these refusals; the record says `deny` with
  the note `placeholder`.

The model is also told the truth about placeholders. Its note on a masked
result ended `the source does not contain placeholders.` even when the source
did; that clause is now said only when the event holds no placeholder-shaped
text at all, and shim's own numbers start above any it holds.

## Placeholder numbers hold for a whole event

- **One value, one number.** Within one prompt or one tool event a value
  always gets the same number and two values never share one, across every
  field and the converted page. Before, numbers restarted for every field, so
  two people could both be `<EMAIL_1>`, and one value repeated could become
  `<EMAIL_1>`, `<EMAIL_2>` and `<EMAIL_3>`. One account, card or phone written
  with different spacing, hyphens or case is one value. Numbers can skip but
  never repeat, and they start again with the next event: the numbering lives
  in memory for that event only, and no value or fingerprint is written down.
- **Line numbers stay true.** A masked span that covered line breaks, such as
  a PEM key or a wrapped base64 block, keeps them after its placeholder, so the
  line numbers of a `Read` after it are right.
- **The `html` diet scans the page once, as the model reads it.** A page is
  converted first and then scanned, so an IBAN split across two `<span>`s is
  masked whole; in 1.2.2 its first groups reached the model. A value that runs
  across tags (`password=<b>...</b>`) is masked in the markup before
  conversion. A page that cannot be converted, or whose text cannot be scanned
  in full, is handed on as masked markup, never converted.
- **`[reveal]` shows the right digits.** A tail is read from the decoded value
  alone, in ASCII digits, so a percent-encoded IBAN shows its own last digits
  and a card beside a phone number never shows the phone's.
- **Text shim already masked is not counted again** by the `Stop` count or
  `shim audit` as a secret the model wrote, with one exception under "Known
  gaps".

## Keys, numbers and files in tool payloads

- **Keys and numbers are inspected.** An email address used as a JSON object
  key is masked in the key, and a card, national ID or phone number sent as a
  JSON number is found and counted; to an MCP tool, such a call is refused
  under the default `enforce`. A whole float such as `9.05e11` is read as the
  integer it is.
- **A value is read with its key.** `{"password": "..."}` and a
  `{"name": "DB_PASSWORD", "value": "..."}` pair are masked. Past 4,096
  characters only the start of a value is read with its key, unless the key
  starts a finding there.
- **A file's bytes are never rewritten.** A `Read` of an uncompressed PDF
  holding a credential used to have its `file.base64` replaced by
  `<SECRET_1>`. Now a finding in a file's bytes, or in keys that masking would
  make collide, withholds the result under `enforce`, saying what it held:
  `shim: withheld this Read result; it holds SECRET (1), which a placeholder
  cannot replace without breaking it.` A call is refused with `A placeholder
  cannot replace it without breaking the call.` added. `observe` only records
  it and `warn` only reports it.
- **A real image passes unread.** In a tool result, a PNG, GIF, WebP or JPEG
  with a readable header and nothing but base64 in it reaches the model as a
  picture, and its bytes cost no time: an MCP image, a `Read` image, a `Read`
  parts page. Anything else, including an image a call sends out, is read.
- **Cost.** Text `Read`s cost the same as in 1.2.2. A result near 1 MB dense
  with keys takes 4 to 10 s against 0.2 to 2 s in 1.2.2, inside the deadline.

## What the detector finds

- **Any `scheme://user:password@host`.** The user and password in
  `postgresql+asyncpg://`, `mysql+pymysql://`, `mariadb://`, `clickhouse://`
  and `sqlserver://` URIs are masked as `DB_URI`, and in `amqp://`, `smtp://`,
  `ssh://`, `ldap://` and every other scheme as `SECRET`, also when the
  password is percent-encoded and on a line a diff adds or removes. An `https`
  URL with an encoded password, once reported as `EMAIL`, is a `SECRET`.
  References such as `${X}`, `***` and `%X%`, and an image pinned by a
  `sha256` digest, are left alone.
- **Secret key names.** A key with the secret word glued on (`PGPASSWORD`,
  `DBPASSWORD`, `SECRETKEY`, `ACCESSTOKEN`, `OPENAIAPIKEY`, `registrytoken`)
  or followed by digits, `_` or `.` (`PASSWORD2`, `PGPASSWORD_PROD`) masks its
  value; `BYPASS` and `COMPASS` stay quiet. A typed declaration masks its
  initializer in Python, TypeScript, Kotlin, Swift and Rust
  (`db_password: str = "..."`). Maven `<password>` elements, `<entry>` and
  `<property>` forms, Kubernetes and ECS `name:`/`value:` lists, AWS SSM name
  and value pairs and a Terraform variable's `default` mask their value. A
  template placeholder such as `<your-api-token>` is not a secret.
- **A digit-only password is masked** under a key whose last word is a
  password word (`DB_PASSWORD=12345678`, `REDIS_PASSWORD`, `SMTP_PASS`), and a
  random password under such a key is no longer let through for looking like a
  path or a call; code written in names (`config.db_password`) still is.
- **The mask covers exactly the value.** In
  `<add key="DbPassword" value="..."/>` the placeholder used to land on
  `value=` while the value stayed in clear; now the value attribute is masked,
  quoted or not, and an unquoted one runs to whitespace or `>` as a browser
  reads it. A connection string keeps its options
  (`Server=db;Password=<SECRET_1>;Encrypt=true`) and a URL its later
  parameters. A percent-encoded quote or separator inside a password no longer
  ends it early. A password in escaped JSON, as structured logs and AWS
  Secrets Manager's `SecretString` print it, is masked.
- **Where a value's end is ambiguous, the mask runs through.** In a `.env` line
  such as `PASSWORD=s3cr3tPass|next`, the trailing `;`, `&` or `|` text can be
  part of the password, so it is masked with it: `PASSWORD=<SECRET_1>`. A
  password is never partly exposed.
- **Addresses keep their paths.** A path or URL that holds an address keeps
  its host and folders: `https://api.example.com/v1/users/<EMAIL_1>` and
  `/work/<EMAIL_1>/notes.txt`, where 1.2.2 hid everything before the address,
  a Google Drive folder named after one included. A git remote ending in
  `.git` (`git@github.com:org/repo.git`) is no longer masked as an address;
  `email:password` lines still are.
- **Context cues in code style.** A Turkish tax ID after `TAX_ID=`, `taxId`,
  `taxpayerId`, `vergiKimlikNo` or `alıcıVkn`, and a phone number after
  `phoneNumber`, `mobileNumber`, `contactPhone`, `cepTelefonu` or in a vCard
  `TEL;TYPE=CELL:` line, are masked. `siparişNo`, a false phone cue in 1.2.2,
  no longer is one. Expect a little more noise: camel-case keys on the generic
  `no` (`userNo`, `lineNo`, `pageNo`) now mask a number as `user_no` already
  did, and a tax-prefixed key such as `taxRate` beside a 10-digit number with a
  valid checksum masks it as a tax ID. `orderNo`, `refNo` and `faturaNo` stay
  unmasked.

The detector corpus grows from 752 to 855 cases (`guard-v2` 335, `reveal-v1`
11). `parity-v1.json` is untouched: 405 of its 475 cases remain
byte-identical, and the three private keys that now keep their line breaks are
pinned with their reason beside the earlier deliberate differences.

## Session records and the ledger

- **Records are scrubbed with your settings.** On an event shim could not
  inspect, for a file attached with `@`, and for an MCP tool's name, a value
  that only a custom pattern or an opt-in type matches used to be written into
  the record as it was. Every record's path and tool name is now scrubbed with
  every type you enabled or named, every default type and your custom
  patterns. A `[reveal]` tail never reaches a record or the ledger, and a
  value split by an invisible character is found before it is stored.
- **`[entities]` keyed by the prompt event now applies to prompts.**
  `UserPromptSubmit = ["EMAIL"]` narrows the prompt and the files attached
  with `@`; in 1.2.2 it was ignored. That also turns off `SECRET` and `CUSTOM`
  for prompts, so an AWS key typed into one then passes without a word.
- **Records are not dropped.** Parallel hook events used to lose a session or
  ledger record whenever two met at the lock, so a summary undercounted
  without saying so. Each append and read now waits up to 100 ms. A record
  still lost makes the next summary say the log is incomplete, and a session
  whose only record was lost shows that note alone.
- **A short ledger says so.** When a retained month reached its 5 MB cap or
  lost an event, `shim ledger show` and the `shim report` fallback print a
  `WARN`, and `--json` carries `"capped": true`.
- **`shim doctor` checks the ledger folder** while the ledger is on
  (`LEDGER_FOLDER_UNSAFE`, with the `chmod 700` that fixes it), so the fix
  `LEDGER_UNREADABLE` points at now exists.

## The answer arrives before the client stops waiting

A client kills a hook that runs past the timeout shim registered, and Claude
Code then goes on as if no hook had run. In 1.2.2 the hook counted its 25
seconds from when Python reached `main`, so on a starved machine (CI, low-power
mode, many hooks starting at once) the refusal could come after the client's
30 seconds and the event went through uninspected.

The hook now counts from when the client started its process, as the kernel
recorded it on macOS and Linux, and stops inspecting at 20 seconds. A hook that
starts too late still reads the event and refuses it in that event's own form:
a call denied, an MCP result withheld. If even the refusal is not out at 25
seconds, a fixed refusal for the event is written once and whole. A refusal
that failed used to write nothing; it now gets the fixed refusal. A machine
frozen for longer than that, as one put to sleep, can still miss the timeout.

## Installing, doctor and settings

- **Refusals say why and how to fix it.** A group-writable settings file
  (umask `002`) was blamed on another user; its fix is now `chmod g-w,o-w` on
  the file or folder that needs it, and a relative client folder asks for an
  absolute `CLAUDE_CONFIG_DIR`, `CODEX_HOME` or `COPILOT_HOME`. A hook group
  where shim's hook sits beside another hook names that reason instead of
  asking you to make a file parse that already parses. A folder others can
  write to is no longer reported as a race. The human output prints the fix
  too.
- **`SHIM_CONFIG` naming a missing file is refused,** as is a settings path
  through a folder link that dangles. Both used to run the shipped defaults
  silently, dropping a `user-prompt = "enforce"` or your custom patterns; now
  the hook fails closed as for any refused file. A relative `XDG_CONFIG_HOME`
  is ignored, as the XDG specification asks. With no settings file at all,
  `shim config` and `shim doctor` now say the shipped defaults apply.
- **`[mode] default` that turns masking off is warned about.** `default`
  outranks the shipped per-direction modes, so `default = "warn"` switches off
  the masking of tool results and of tool inputs that leave the machine.
  `shim doctor` now warns with `MODE_DEFAULT_WEAKENS`.
- **Custom patterns that cannot run are flagged.** While `CUSTOM` is off,
  `shim config` lists them as `Custom (off)` and doctor warns with
  `CUSTOM_PATTERNS_INACTIVE`.
- **Doctor sees the right plugins.** It reads Claude Code's plugin list under
  `CLAUDE_CONFIG_DIR`, skips a plugin `enabledPlugins` turns off, and with two
  shim plugin keys names both instead of crashing.
- **Settings errors name the file that was refused,** the 0.2.0 file the hook
  falls back to included, with a fix for that path. A 0.2.0 settings file left
  beside a current one gets an `rm` fix instead of a `shim config` that never
  moved it.
- **A failed 0.2.0 settings move is a `WARN`,** not a traceback, and the
  install goes on.
- **Install says what it does.** It asks `Append shim after existing Claude
  Code hooks?` only when there are some, and `--dry-run` says the file is
  rewritten with 2-space indentation, where it used to promise nothing else in
  the file changes.

## `shim audit` and `shim keys`

- **`shim audit --purge`** with a `history.jsonl` that is a link or not a
  regular file refuses and deletes nothing. In 1.2.2 it deleted the
  transcripts and kept the prompt lines.
- **`shim audit` no longer says `safe` after skipping.** When nothing was found
  but lines were skipped or texts left uninspected, it reports `incomplete`
  and exits `1`.
- **`already masked by shim` is counted from shim's own records,** the open
  session's log and the ledger if it is on, not from placeholder-shaped text in
  the transcript. Without the ledger an ended session counts nothing there, and
  the line says `(without the ledger, live sessions only)`.
- **`shim keys --json`** on an unreadable file prints a JSON error with the new
  code `FILE_UNREADABLE`, not a usage error.

## What to check after upgrading

- **Write-back refusals:** a `Write`, `Edit` or MCP call that carries a
  placeholder shim issued in the session is now refused in every mode,
  `observe` included. If an agent stops on one, change the value another way;
  a placeholder that is really part of the text (a doc, a fixture) is refused
  only in a session where shim issued that exact name.
- **`SHIM_CONFIG`:** if it names a file that does not exist, every prompt is
  now withheld and tool events refused until the file exists or the variable
  is unset. `shim config` prints why.
- **`[mode] default`:** if `shim doctor` warns `MODE_DEFAULT_WEAKENS`, tool
  results have not been masked; add `inbound = "enforce"` and
  `outbound = "enforce"`.
- **`[entities]` keyed by `UserPromptSubmit`** now narrows prompts. Check that
  the list keeps `SECRET` and `CUSTOM` if you rely on them there.
- **Tool results withheld after inspection:** a PDF or other file holding a
  credential is withheld under `enforce` rather than rewritten.
- **MCP calls:** keys and numbers are now inspected, so an MCP call carrying a
  card or phone as a JSON number, or a short value under a `token` or
  `API_KEY` key, such as a `pageToken`, is refused under the default
  `enforce`. `"<tool name>" = "warn"` under `[mode]` reports it instead.
- **Scripts that read output:** `shim audit` exits `1` with
  `"status": "incomplete"` when it skipped something; `shim ledger show
  --json` and `shim audit --json` carry `capped` and `masked.ledger`; `shim
  keys` adds `FILE_UNREADABLE`; doctor adds `SETTINGS_FILE_ABSENT`,
  `CUSTOM_PATTERNS_INACTIVE`, `MODE_DEFAULT_WEAKENS` and
  `LEDGER_FOLDER_UNSAFE`; the `CLIENT_SETTINGS_UNSAFE` and
  `CLIENT_SETTINGS_MALFORMED` fixes and the install prompt changed. Match
  `code`, never the text.
- **The hook's deadline is 20 seconds from process start,** not 25 from
  `main`, so a very large event reaches it a little sooner and is withheld or
  refused, as before.
- **Downgrading:** 1.2.2 ignores the placeholder names store and writes
  placeholders back again, numbers placeholders per field, and runs the
  defaults when `SHIM_CONFIG` names a missing file.

## Known gaps

These are known and not fixed in 1.2.3.

- **Number-dense text can still reach the deadline** (held back). The 1.2.2
  notes' figure for `- 0 - 0 - 0` repeated was measured before a late 1.2.2
  fix; that shape reads at about 1.4 s per MB. One line of single digits in no
  repeating order joined by ` - `, `/` or `–` still reads at about 10 to 25 µs
  per character on an M1, depending on load, so toward the 1 MB bound such a
  line can reach the 20-second deadline. It is then withheld or refused, or,
  where shim can only report (a failed call's output, a VS Code result, a file
  attached with `@`), reported as not inspected while the model has it. The
  same text split into lines is about ten times faster. A megabyte of distinct
  valid phone numbers takes about 5 to 10 s. `@` mentions after `。`, `、`,
  `？` or `！` can make a very long prompt slow to read, and a long
  `shim watch` holds its phone memos in memory without a bound.
- **Pattern coverage** (held back). PGP and DSA private key blocks, Stripe
  restricted keys (`rk_live_`), Slack app tokens (`xapp-`), GitLab runner and
  deploy tokens, `Proxy-Authorization: Basic`, an undelimited 9-digit SSN
  after `ssn`, and 18- or 19-digit cards are not detected. An address that is
  only an address before percent-decoding, such as one split by an encoded
  space, is missed. A Turkish instruction-override line that starts like a
  commit subject (`fix: `) is not flagged. `shim config` accepts some custom
  patterns that backtrack, or that only backtrack with `ignore_case`.
- **MCP refusals on detector noise** (held back). Under the default `enforce`,
  any finding in an MCP call refuses it, so a false positive in ordinary input
  refuses an ordinary call; `pageToken` and short values under `token` or
  `API_KEY` names are known examples. A per-tool `[mode]` key is the way
  around it.
- **Counted again.** Outside a list, where the mask runs through trailing
  text, `password=<SECRET_1>&user=app`, `Password=<SECRET_1>;Encrypt=true` and
  `PASSWORD=<SECRET_1>|next` are still counted by the `Stop` count and
  `shim audit` as a secret the model wrote. In a URL query or a connection
  string they are not.
- **Detection limits.** A digit-only password under a key whose last word is
  not a password word (`PGPASSWORD_PROD=12345678`), a password that is `$` and
  an identifier, and a password written in names that reads as code
  (`correct.horse.battery`) pass. In a URI outside the database family, a raw
  `/`, `?` or `#` in the password ends the user-info, so it is not matched; its
  encoded form is. A value field before its name field, a literal wrapped in a
  call (`SecretStr("...")`) and a name and value more than 256 characters apart
  are not paired. Phone cues still missed: `CONTACTPHONE`, `phoneHome`,
  `Tel1:`, a quoted vCard parameter with a space, `telefonlar`.
- **Noise.** `git@host:org/repo` without `.git` and `ssh://git@host/...`
  remotes are masked as addresses. A `printf` template such as
  `"%s://%s:%s@%s"` is masked as a `SECRET`. The pair and element forms mask a
  template expression such as `{{ .Values.db.password }}`. A `:value=` or
  `@input=` binding after a secret's name attribute gets its attribute name
  masked, as in 1.2.2.
- **Records.** An image passed unread is not counted, so the summary cannot
  tell it from a result with nothing found. A record's 512-character target
  window can start inside a secret on a very long path. A `[[custom]]` literal
  joined to other word characters, as in an MCP tool name, is not matched. A
  `Stop` summary whose read waits past 100 ms is not shown that turn, and a
  ledger folder that cannot be opened leaves no marker; `shim doctor` reports
  it.
