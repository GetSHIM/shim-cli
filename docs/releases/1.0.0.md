# shim-cli 1.0.0

1.0 no longer runs the names 0.2.0 wrote. The `shim_guard` package, the
`shim-guard-hook` script, the `SHIM_GUARD_CONFIG`, `SHIM_GUARD_STATE_DIR` and
`SHIM_GUARD_SESSION_DIR` variables and the `shim-guard` marketplace entry are
gone. A client settings file that still carries `-m shim_guard.hook` makes the
client report a hook error on every prompt (`No module named shim_guard`, exit
1, which Claude Code shows and does not block on) and nothing is inspected
until you run `shim install <client>` once. `shim doctor <client>` reports that
shape as `FAIL` with the same command. Settings, the ledger and the Copilot hook
file still move on first contact. A plugin installed as `shim-guard@shim-guard`
stopped updating at 0.3.2; move it with `/plugin uninstall shim-guard@shim-guard`,
`/plugin marketplace add GetSHIM/shim-cli` and `/plugin install shim-cli@shim-cli`. Set `SHIM_CONFIG` where you set the old
settings variable; the ledger follows `XDG_STATE_HOME` and session records
follow `TMPDIR`.

Everyone else: upgrading is `uv tool upgrade shim`, or
`/plugin update shim-cli@shim-cli` in Claude Code. There is nothing to migrate.

## What a Claude Code user gets

- Secrets and personal data masked in eligible tool results before the model
  reads them, and the model told what was masked, so it does not mistake a
  placeholder for the file's contents.
- A report of what was in your prompts; blocking is opt in.
- A session summary at the end of a turn where something changed, and
  `shim report` on demand.
- `shim watch -- claude`: what the session sent and what came back, in both
  directions, with token counts from the provider.

## What a Codex user gets

The prompt hook only: a report of what was in the prompt, and a block under
`enforce`. No tool results are inspected and nothing is measured: `shim watch`
refuses Codex, because Codex takes its endpoint from its own configuration and
the proxy would measure an empty session.
[The September 2026 probe](../probe-2026-09-codex-watch.md) shows the transport
works, so this has a fix. The hook runs only after you trust it in `/hooks`.

## What a Copilot user gets

Prompt replacement: the model receives the redacted prompt through
`userPromptTransformed`. The original can stay visible in Copilot's timeline.

## What is approximate

- The section split in `shim watch` (tools, system, messages) is inferred from
  byte share and marked `~`; token totals are exact.
- Spend is priced from the 2026-08-30 price table. On a subscription it is what
  the same traffic would cost on an API key, not a bill.

## What is not in 1.0

Candidates for 1.1, in this order:

- `shim watch` for Codex.
- Keeping the price table current.
- Token cost by language, starting with Turkish.
- An image cost line in the watch report.

Also not in 1.0: a bare phone number in a non-Turkish national format with no
cue such as `tel` or `phone` nearby is not detected. A custom pattern covers it.

## Verified

`python scripts/check.py` green on the candidate: 1,987 tests, lint, format,
types and a package build; CI covers 3.10 and 3.13 on macOS and Ubuntu, and the
committed archive answers identically on Python 3.9 and 3.13.

Walked live before the tag, each client in an isolated configuration: Claude
Code 2.1.263 from the marketplace with only the system Python 3.9 on `PATH`
(prompt report, a JSON file left intact, a `.env` masked and the model saying
so, the session summary, `shim watch` on a subscription); Codex CLI 0.151.0
from the marketplace (`Blocked` under `enforce`, `Completed` under `observe`,
`shim watch` refused with its sentence); the package installed with
`--python 3.12` on a 3.9-first `PATH`; a machine upgraded from 0.2.0 taken
from doctor's `FAIL` to clean with `shim install`; and `shim revert` leaving
unrelated settings as they were; GitHub Copilot CLI 1.0.83 (the model received
the redacted prompt, and a failing hook let the prompt through). Every quoted
screen is in [compatibility.md](../compatibility.md).
